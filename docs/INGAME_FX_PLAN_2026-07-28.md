## 第0部: 実測でわかった今の状態

ブラウザで 390×844（iPhone 相当）を実際に動かして測った数字。推測ではない。

### ① 盤面の下に 63px の死に余白がある

| 測ったもの | 値 |
|---|---|
| 盤面（board-wrap）の高さ | 620px |
| 自分の一番下のカードの下端 | y=596 |
| 手札の箱の上端 | y=659 |
| **何も無い区間** | **63px（盤面の10%）** |

**原因**: `.zone-col`（山札・AP・トラッシュの縦3段）の高さが **276px**、陣形は **207px**。
`.my-area` は `align-items: flex-start` なので、**ゾーン列の余った 69px がそのまま下にぶら下がる**。
カードの大きさとは一切関係なく、ただ捨てられている縦。

### ② FIELD枠は「重なっている」どころか実質見えない

| 測ったもの | 値 |
|---|---|
| FIELD枠 | 42×57（y329〜387） |
| 相手アクターの下端 | y=346（**上から17px食う**） |
| 自分アクターの上端 | y=372（**下から15px食う**） |
| 素通しで見えている縦 | **ほぼ0px** |

しかも `<CardFrame width={40}>` なので、仮に見えていても絵も文字も読めない。
**中央は敵味方のアクターが向かい合う場所**なので、ここに置く限り構造的に必ず潰れる。

### ③ 左右がそろっていない

- 相手アクターの中心 **x=217** / 自分アクターの中心 **x=187** → **30pxズレて向かい合っている**
- 自分の山札・AP・トラッシュは画面外へ 29〜40px 出ているのに、**相手の山札だけ 0px**（はみ出していない）
- 原因: `.zone-col` が片側だけ 26px の場所を取るので、陣形の中心が左右にズレる

### ④ カードの物理: 1枚のカードが3つの別オブジェクトになっている

カードを1枚使うと、画面ではこう見えている。

| 見えるもの | 正体 | 大きさ |
|---|---|---|
| 手札のカード | **消えるだけ**（動かない） | 78px |
| 画面中央にポンと出るカード | `.reveal`（別のDOM） | 190px |
| トラッシュへ飛ぶカード | `FlyGhost`（また別のDOM） | 54px |

ドローも同じで、飛ぶのは **34pxの裏面画像**、着地したあとに手札が別途生える。
さらに飛ぶカードは `position: fixed` なので、**3Dに傾いた卓の外**を平面移動している。
（自分の手札も卓の外、相手の手札は卓の中、という不整合もある）

**良い知らせ**: `useBattle` は既に「演出イベント1件ごとに表示状態を1段ずつ進める」作りになっている。
つまり **「カードが飛んでから枚数が減る」ための土台はもう出来ている**。あとは飛ぶものを本物にするだけ。

## 第1部: A. 物理挙動を「本当のカードの動き」にする

### 決めたコンセプト（先に体験、あとから仕様）

> **1枚のカードは、最初から最後まで1枚のカードである。**
> 山札の一番上から持ち上がり、手札で立ち、卓の上に寝て、トラッシュに重なる。
> 途中で別のものにすり替わらない。

### A-1. カードレイヤーを1枚作る（土台・これが最初）

- `.battle-root` の直下に `position:absolute; inset:0; pointer-events:none` の **カード舞台**を1枚敷く
- 舞台は `.board` と同じ `perspective: 950px` / `perspective-origin: 50% 26%` を持つ
- 飛んでいるカードは全部ここに住む。`.reveal` も `FlyGhost` もここへ統合して消す

**「立つ／寝る」を持たせる**のが肝。

| 場所 | 姿勢 | 傾き |
|---|---|---|
| 手札 | 立っている（自分に正対） | `rotateX(0)` |
| 卓の上・山札・トラッシュ・AP | 寝ている（卓に沿う） | `rotateX(15deg)` |

移動中はこの2つの間を補間する。**「山札から起き上がって手札に来る」「手札から卓へ寝かされる」**という
紙の動きが、これだけで出る。

**触る所**: `web/src/battle/CardStage.tsx`（新規）、`web/src/battle/BoardParts.tsx`（FlyGhost 削除）、`web/src/pages/Battle.tsx`（reveal 削除）
**完了の判定**: 飛んでいるカードが卓と同じ角度で傾いて見える／`.reveal` と `FlyGhost` がコードから消えている
**規模**: 中 / **リスク**: 中

### A-2. 移動の指示を1本のAPIにまとめる

いまの `spawnFlight(fromEl, toEl, count, faceCardId)` を置き換える。

```ts
flyCard({
  cardId,                 // 無ければ裏のまま
  from, to,               // DOM の矩形（画面座標）
  face: '裏→表' | '表→表' | '表→裏',
  pose: '寝→立' | '立→寝' | '寝→寝',
  arc,                    // 弧の高さ
  hold,                   // 途中で止まる時間（使用時のカットイン）
  spin,                   // 横倒し（チャージ用）
  onArrive,
})
```

**触る所**: `web/src/battle/CardStage.tsx`、`web/src/pages/Battle.tsx`（イベント→演出の割り当て）

### A-3. 各イベントに割り当てる動き

| イベント | どこから | どこへ | 面 | 姿勢 | 特記 |
|---|---|---|---|---|---|
| **ドロー** | 山札の天面 | 手札の着地位置 | 裏→表 | 寝→立 | 着地の瞬間に表へ翻る |
| **使用（play/guard）** | **手札のそのカード** | 卓の中央（0.7秒止まる）→ トラッシュ | 表→表 | 立→寝 | **今の reveal はこの途中経過として吸収** |
| **チャージ** | 手札のそのカード | APの山 | 表→裏 | 立→寝 | 90°横倒しになりながら重なる |
| **フィールド展開** | 手札のそのカード | 情報帯のFIELD枠 | 表→表 | 立→寝 | 置きっぱなし |
| **装備** | 手札のそのカード | 対象キャラの足元 | 表→表 | 立→寝 | カードの下に半分挿し込む |
| **デッキから落とす（mill）** | 山札 | トラッシュ | 裏→表 | 寝→寝 | 表に翻ってから落ちる |
| **デッキからチャージ** | 山札 | AP | 裏→裏 | 寝→寝 | |
| **トラッシュからチャージ** | トラッシュ | AP | 表→裏 | 寝→寝 | |
| **APトラッシュ** | AP | トラッシュ | 裏→表 | 寝→寝 | |
| **トラッシュ→デッキ** | トラッシュ | 山札 | 表→裏 | 寝→寝 | |
| **サーチ** | 山札 | 中央で0.5秒見せる → 手札 | 裏→表 | 寝→立 | 何を持ってきたか見せる |
| **戦闘不能** | その場 | その場 | 表→裏 | — | 今の `ko-back` を「めくれる」動きに |

**完了の判定**: 上の12種すべてで、**手札／山札／トラッシュの実物が動いて見える**（別物が飛ばない）
**規模**: 大 / **リスク**: 中

### A-4. 山に「厚み」を出す

いま山札もトラッシュもAPも **常に1枚の絵**。枚数は数字でしか分からない。

- 枚数に応じて `min(枚数, 6)` 段を 0.6px ずつずらして重ねる
- 減ると薄くなる。増えると厚くなる。**触っていないのに枚数が体で分かる**

**触る所**: `web/src/battle/BoardParts.tsx`（ZoneCol）、`web/src/battle.css`
**完了の判定**: 山札40枚とトラッシュ2枚が、数字を読まなくても見分けられる
**規模**: 小 / **リスク**: 低

### A-5. 着地に重みを付ける

- 到着した瞬間に `scale(1.04) → 1.0` の沈み込み（80ms）と、影が一瞬広がる
- 手札に着地したら、隣のカードが 4px 押されて場所を空ける
- 落下の速度カーブは「最後にストンと落ちる」形にする（今は等速に近い）

**完了の判定**: カードが「置かれた」音（既存の `se_card`）と沈み込みのタイミングが合っている
**規模**: 小 / **リスク**: 低

## 第2部: C. 表示位置を作り直す（案2: 中央に情報帯）

**先にこれをやる。** 物理演出は「どこからどこへ飛ぶか」で決まるので、置き場所が動くと全部やり直しになる。

│AP│控│  │相手  │  │控│  │
│ト└──┘  │アクタ│  └──┘  │
│         └────┘        │
│┏━━━━━━━━━━━━━━━━━━━┓│

### C-1. 死に余白 63px を潰す（最初にやる）

- `.zone-col` を `position: absolute` にして、`.my-area` / `.enemy-area` の高さ計算から外す
- これで area の高さ＝陣形の高さになり、下にぶら下がる 69px が消える

**触る所**: `web/src/battle.css`（`.zone-col` `.area`）
**完了の判定**: 自分の一番下のカードの下端と手札の上端の差が **63px → 20px以下**
**規模**: 小 / **リスク**: 低

### C-2. 情報帯を作る

- `.board` の中、相手エリアと自分エリアの間に **高さ約70pxの帯**を置く
- 帯は**絶対に何も重ならない領域**として確保する（ここが今との一番の違い）
- 読みやすさのため、帯だけ `rotateX(-15deg)` で起こして正対させる

**中身（左から）**:
1. **FIELD枠** … 幅56〜64px。**絵とカード名が読める大きさ**。空なら点線枠に「FIELD」
2. **ターン数 + フェーズ進行** … 「T3 ｜ メイン → チャージ → 相手」。今の `info-bar` から移す
3. **ダメージ予定** … カードを掴んでいる間だけ「9 → 3」と点灯（B-2 と同じ場所）

**触る所**: `web/src/pages/Battle.tsx`（center-strip を作り直す）、`web/src/battle.css`
**完了の判定**:
- FIELDカードにキャラのカードが **1pxも重ならない**
- FIELDカードの名前が実機幅で読める
- 情報帯の高さが 60〜80px に収まる

**規模**: 中 / **リスク**: 中

### C-3. カードの大きさの式を実測ベースに直す

`cardWidthFor()` の `budget = 0.3 × 画面高 + 9` は、実際に使える縦（実測582px）よりかなり少なく見積もっている。
情報帯を入れると陣形に使える縦が減るが、**C-1で63px戻るので、差し引きではむしろ余る計算**。

```
今:  center-strip 49px + 死に余白 63px = 112px
後:  情報帯 70px                        = 70px   →  42px 余る
```

ただし「アクターが情報帯に食い込まない」ようにするには、前へのせり出し係数（今 0.58）と
縦半径 `ry`（今 0.6）を浅くする必要があり、そのぶんは食われる。
**最終的なカード幅は実測しながら決める。数字を先に決め打ちしない。**

**触る所**: `web/src/pages/Battle.tsx`（`cardWidthFor`）、`web/src/battle/BoardParts.tsx`（`ry` とせり出し）
**完了の判定**: 13サイズ全部で「カード同士の重なり0」かつ「情報帯への食い込み0」。カード幅は今（106px）を下回らない
**規模**: 中 / **リスク**: 中（ここを間違えると全画面で崩れる）

### C-4. 敵味方アクターの中心をそろえる

- 今は 30px ズレている。C-1 でゾーン列を絶対配置にすれば、両エリアの陣形が同じ幅で中央に来る
**完了の判定**: 相手アクターと自分アクターの中心の差が **2px以下**
**規模**: 小 / **リスク**: 低

### C-5. 左右のはみ出し量をそろえる

- 相手の山札だけ画面外へ出ていない。自分と同じだけ出す
**完了の判定**: 6つのパイルすべてで、画面内に見えている幅が **24px以上・40px以下**
**規模**: 小 / **リスク**: 低

## 第4部: D. 操作をドラッグにする（社長判断: やる）

**物理レイヤー（A-1）ができてから着手する。** 掴んで動かす仕組みはA-1とそのまま同じものを使う。

### D-1. 掴む
- 手札を押した瞬間、そのカードが**指の下で立ち上がる**（少し浮いて拡大）
- 指に追従する。カード舞台（A-1）の上を動く

### D-2. 置ける場所を光らせる
- 合法手（`legalActions`）から導く。今の `targeting` の仕組みをそのまま流用できる
- 攻撃なら相手キャラ、回復なら味方、装備なら味方、フィールドならFIELD枠、チャージならAPゾーン

### D-3. 離す
- 置ける場所の上なら、そこへ置かれる（＝A-3の「使用」の動きにつながる）
- 置けない場所なら、**バネで手札へ戻る**

### D-4. チャージもドラッグに統一
- 「APゾーンへドラッグ」でチャージ
- これが効くと **「チャージへ →」ボタンと「N枚チャージしてターンエンド」ボタンが要らなくなる**可能性がある
- 1ターンの手数が 3〜4 → 1〜2 に減る

### D-5. タップは「見る」に戻す
- 単押し＝プレビュー拡大。長押しは要らなくなる
- 今の「タップ→モーダル→使う→対象選択」の4手は消える

### D-6. マウスとタッチ両対応
- Pointer Events で書く（今の `handPeek` も Pointer Events なので方針は同じ）

**完了の判定**:
- 攻撃・回復・装備・フィールド・チャージのすべてがドラッグで完了する
- 途中で指を離しても状態が壊れない（必ず手札に戻る）
- **1ターンの平均タップ数を実測して記録する**（今の値も先に測っておく）
- PCのマウスでも同じ操作ができる

**規模**: 大 / **リスク**: 中〜高

### 2026-07-29 第8段階（D ドラッグ操作）完了

**手札のジェスチャを1か所にまとめた。**

| 動き | 結果 |
|---|---|
| 押して**動かす** | カードを掴む。置ける場所が光り、置いたらどうなるかが出る |
| 置ける場所で**離す** | そこへ置かれる（＝カード使用・装備・フィールド・チャージ） |
| 置けない場所で**離す** | 手札へ戻る（何も起きないことを目に見える形で伝える） |
| **動かさず長押し** | 拡大して見る（従来どおり） |
| **動かさずタップ** | プレビューを開く（従来どおり。従来の操作は残してある） |

**置き場所は合法手（`legalActions`）から導出する。UIで推測しない。**
対象を選ばないカード（＝大半の攻撃）は、効果定義の `targeting` から
「どこへ向けるカードか」を決めて、その相手を光らせる。

**掴んでいる間に「置くとどうなるか」が出る。** 対象選択モードの仕組みをそのまま
使っているので、B-2 のダメージ予定がここで本来の形になった（実測で `12→10` を確認）。

**指の追従は state ではなく DOM を直接動かす。** 1フレームごとに setState すると
バトル画面まるごとが再描画されて指に付いてこない。状態に持つのは
「どのゾーンの上にいるか」が変わった瞬間だけ。

**実測で確かめたこと**

| 確認 | 結果 |
