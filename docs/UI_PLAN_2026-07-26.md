# ポケポケのUI分析と、BRAVER'S DUEL の改修計画

- 2026-07-26 初版（見た目の比較だけ）
- 2026-07-27 全面改訂（開発者の設計思想・操作の挙動まで踏み込んで書き直し）

調べたもの: CEDEC 2025 の開発者講演2本、ファミ通の開発者インタビュー、公式サイト、
攻略サイトのルール解説、UIデザイナーによる観察記事、実際のプレイ画面のスクリーンショット。

## 第1部: ポケポケが何を考えて作られているか

### 1-1. 決め方の順番が「コンセプト → ターゲット → UX → 仕様」

DeNAの総合ディレクターが CEDEC で明かしている進め方。**先に体験を決めて、それを実現する
仕様を後から考える**。例として挙げられていたのが、

> 「ポケモンカードらしさを大切にする」というコンセプト
> → カードを手に入れた時のUXは「開封のワクワクを体験できるようにする」
> → 仕様は「パックをスワイプで開ける」

**ここが一番の学び。**「この機能を付ける」から始めず、「どういう気持ちにさせたいか」から始めている。
うちで言えば「物理的にTCGしてる感じ」というコンセプトは既にあるので、
**各画面ごとに「どういうUXか」を一文で決めてから仕様を考える**とブレなくなる。

### 1-2. 「自分が結果に関与している感覚」を必ず作る

ポケポケは、**結果がランダムな場面ほど、プレイヤーの指を介在させている**。

- コイントス: 指でスワイプした軌跡でコインが飛ぶ。強く弾けば高く遠く、弱ければ低く近く
- パック開封: 指でなぞった線がそのまま切れ目になる
- パック選択: パックを360°回して、裏返して、折れ目まで見てから選べる

結果は乱数なのに、**自分が関わったことにできる**。だから納得して受け入れられる。

うちの該当箇所: **先攻後攻のコイン**（今は自動で結果が出るだけ）、**ドロー**、**チャージ**。
ここに指の介在を作れる余地がある。

### 1-3. 紙の手触りをデジタルに翻訳する（ただし翻訳であって再現ではない）

CEDEC の講演では「本作でどれくらいデジタル要素を採り入れるかに気を使った」と明言している。
やっていること:

- カードは **UI層 → カード枠 → 背景 → イラスト** の多層構造。レアリティが上がると層が増える
- ホログラムは位相テクスチャ＋グラデーションで擬似再現
- **傾けると背景の視差がずれる**（視差シェーダでUVをずらす）。マーブル背景は傾けると模様が変わり、正面に戻ると戻る
- 「カードの要素は盛り気味にすることが大事」という方針

つまり**紙では絶対にできない動き（視差・イマーシブ）をあえて足して、「デジタルのカード」の
価値を作っている**。紙の完全再現を目指していない。

### 1-4. スキマ時間に遊べること＝ルールとUIの両方を削る

ファミ通のインタビューで開発者が「スマートフォンへの最適化」「スキマ時間に気軽に」を
最も意識したと述べている。実際に削ったもの:

| | 紙のポケカ | ポケポケ |
|---|---|---|
| デッキ | 60枚 | **20枚** |
| 初期手札 | 7枚 | 5枚 |
| ベンチ | 5枠 | **3枠** |
| 同名 | 4枚 | **2枚** |
| エネルギー | カードとしてデッキに入れる | **エネルギーゾーン（カードではない）** |
| 弱点 | ダメージ2倍 | **一律 +20** |
| 勝敗 | サイド6枚 | **3ポイント先取** |

**弱点が「2倍」ではなく「+20」なのが象徴的。** 暗算できる数字にしている。

### 1-5. 「プレイヤーが損をする体験」を構造的に潰している

ここが一番効いていると思う。

- **マリガン（引き直し）が無い。** 初期手札5枚には**必ず**たねポケモンが1枚入るように仕込んである
- **山札切れは敗北ではない。** 山札が0枚になってもカードを引く処理がスキップされるだけ
- **手札上限10枚。** 手札が増え続けて画面が破綻することがない
- **ベンチは3枠固定。** 盤面の情報量が絶対に増えない

「事故った」「何もできないまま負けた」という体験を、ルール側で先に潰している。

## 第2部: その思想がバトル画面のどこに出ているか（具体の挙動）

### 2-1. 操作は「タップして選ぶ」ではなく「掴んで置く」

- 手札のポケモンは、**バトル場やベンチへドラッグして出す**
- エネルギーは、**右下のエネルギーゾーンからポケモンへドラッグして付ける**

メニューを開いて対象を選ぶのではなく、**物を掴んで置く**。1-3の「紙の手触りの翻訳」がここに出ている。

**うちとの差（重要）**:
うちは「手札をタップ → 全画面のプレビューが出る → 『このカードを使う』を押す → 対象選択モードになる → 対象をタップ」。
**3タップ＋全画面モーダルが1回**。ポケポケは**1ドラッグ**。

### 2-2. 「ワザを使う＝自分の番の終わり」

ワザを選択した時点で自分の番の操作が完了する。確認ダイアログも「ターンエンド」ボタンも要らない。
ワザを使わない時だけ「番を終わる」を押す。

**一番よくやる行動が、そのままターンの区切りになっている。** 手数が最小。

**うちとの差**: うちは「スキルを使う」→ さらに「チャージへ」→ カードを選ぶ →「Nまいチャージしてターンエンド」。
1ターンに最低3〜4アクション必要。

### 2-3. 次のターンの資源を先に見せる

エネルギーゾーンは**画面の右下**（右手の親指の定位置）にあり、
**次のターンに増えるエネルギーが小さく先出し表示**されている。

だから「今ここでエネを付けるか、次のターンまで待つか」を**今のターンで考えられる**。
先が読めることが、そのまま戦略の面白さになっている。

**うちとの差**: うちは次のドローもチャージも見えない。AP以外に先読み材料がない。

### 2-4. 勝利までの距離が常に見えている

3ポイント先取。画面上部に取得ポイントが常時表示され、**あと何回倒せば勝ちかが一目で分かる**。
ポケモンexを倒すと2点、メガシンカは3点と、「一撃で勝負が決まる」瞬間も作ってある。

**うちとの差**: うちの勝利条件は「相手3人を全滅」か「相手の山札切れ」。
**どちらもプレイヤーから距離が見えない。** 特に山札切れは、気づいたら終わっている。

### 2-5. 画面の端は使い切る。切れてよいものは切る（社長のご指摘どおり）

実際の画面を見た結果:

- **相手の手札**は画面上端で切れ、カードの下40%程度しか見えない
- **自分の手札**は画面下端で切れ、上40%程度しか見えない
- **山札・トラッシュ**は左右の画面端にあり、**半分近く画面外**。しかも**縮小せず、盤面のカードと同じ大きさ**
- 上部にUIバーが無い。左端にハンバーガー1つ、右上に小さなラベルだけ
- **空きベンチ枠は半透明の枠線で常に見せる**（3枠の構造が消えない）

結果、**画面中央のほぼ全部が「戦っているカード」に使われている**。

### 2-6. HPは「小さいバー」ではなく「大きい数字」

カードの右上に、白フチの巨大な数字でダメージ量を出す。バーはその下に細く添えるだけ。
遠目でも、多少重なっても読める。

## 第3部: BRAVER'S DUEL との差分

差を3つの層に分けて整理する。**下に行くほど効くが、下に行くほど重い。**

### 層1: 見た目（数字で出る差）

幅390pxで実測。

| 項目 | BRAVER'S DUEL | ポケポケ |
|---|---|---|
| **主役カードの幅** | **92px（画面の24%）** | 画面の45〜50% |
| 左右のゾーン列 | **幅45px×2＝90px（横の23%）を占有** | 画面外にはみ出し。占有ゼロ |
| 上部UIバー | 高さ35px（vs名・T・フェーズ・×1・音・？・投了） | 無し |
| HP表示 | 高さ27pxにバー＋極小の「12/12」 | 数字だけで30px近く |
| 空き枠 | 見せていない | 半透明の枠で常に見せる |

### 層2: 操作（手数の差）

| 場面 | BRAVER'S DUEL | ポケポケ |
|---|---|---|
| カードを1枚使う | タップ→モーダル→「使う」→対象選択→タップ（**3タップ＋全画面モーダル**） | **1ドラッグ** |
| 1ターンを終える | スキル→「チャージへ」→カード選択→「チャージしてターンエンド」 | ワザを選ぶ＝終わり |
| 次の資源 | 見えない | 次のエネを先出し |

### 層3: 体験の構造（ルールに踏み込む差）

| 項目 | BRAVER'S DUEL | ポケポケ |
|---|---|---|
| **山札切れ** | **決着の66〜82%がこれ**（負け条件） | **負けではない**（引く処理をスキップ） |
| 勝利までの距離 | 見えない（全滅 or 山札切れ） | 3ポイントで常時可視 |
| 事故 | 手札が腐ると何もできないターンがある | マリガン無し・初期手札に必ずたねポケモン |
| 盤面の情報量 | 手札の枚数制限なし | 手札上限10枚・ベンチ3枠固定 |

**層3の「山札切れが決着の大半」は、UIの問題ではなく体験の根幹の問題。**
ポケポケは同じ問題に対して「山札切れを負け条件から外す」という答えを出している。
※うちは 2026-07-23 に社長判断で「山札の緊張感を優先」してデッキ40枚に戻した経緯があるので、
ここは**提案に留める**。ただし「決着の7〜8割が山札切れ」は当時の想定（34.8%）とは別物になっている。

## 第4部: 改修計画

### フェーズ1: 見た目（低リスク・即効）

**1-A. ゾーン列を画面端に寄せて、はみ出させる** ★
縮小をやめて半分だけ見せる。「山札」「AP」「トラッシュ」の文字ラベルは消し、枚数の数字だけ大きく。
→ カード幅 **92px → 約115px（+25%）**。リスク低。

**1-B. HPを大きな数字にする** ★
カード右上に白フチの大きな数字、その下に細いバー。
→ βレビューで2回指摘された「HPが見えない」の本丸。今日「隠れない」ようにはしたが、**小さすぎて読めない**問題は未着手。リスク低。

**1-C. 上部の情報バーを畳む**
常時見せるのはターン数とフェーズだけ。vs名・×1・音・？・投了はハンバーガーへ。
→ 縦に約30px。リスク低。

**1-D. 空き枠・戦闘不能枠を半透明で見せる**
3枠の構造が常に見える。NEXT表示とも噛み合う。
→ リスク中（回転する楕円配置と枠が合うか要検証）。

### フェーズ2: 操作（中リスク・体感が大きく変わる）

**2-A. 「タップ→モーダル→使う」を1タップに縮める** ★★
対象が1つに決まるカード（大半がこれ）は、**手札をタップした時点で即使用**。
プレビューは長押しに寄せる（今も長押しで拡大できる）。
→ 1ターンの手数がほぼ半分。リスク中（誤タップ対策として、使用直後に「取り消し」を1.5秒出す等の保険が要る）。

**2-B. ドラッグで出す**
手札をキャラへドラッグして使う。ポケポケの「掴んで置く」の翻訳。
→ リスク中〜高。タッチ実装が増える。**2-A を入れてから、必要なら**。

**2-C. 次のターンの情報を先出し**
次に引く枚数・チャージ後のAP見込みを小さく表示。
→ リスク低。効果は地味だが「先が読める」は戦略ゲームの気持ちよさに直結。

### フェーズ3: 体験の構造（要・社長判断）

**3-A. 勝利までの距離を可視化** ★★
「あと何体倒せば勝ち」を常時表示（例: 相手の生存3体を上部に小さくアイコン表示、倒すと消える）。
→ リスク低。**効果は大きい。** 今は「気づいたら勝っていた／負けていた」になりやすい。

**3-B. 山札切れの扱いを見直す**（提案のみ）
案1: 山札切れでは負けず、引けないだけにする（ポケポケ方式）
案2: 山札切れ時に「残り○ターンで敗北」の警告を出し、少なくとも**見えるようにする**
→ 案2だけでもかなり違う。案1はゲームが別物になるので社長判断。

**3-C. 「何もできないターン」を潰す**
今は手札が腐ると1ターン丸損になる（デッキ組み直しで軽減済みだが、構造は残る）。
初期手札の保証や、腐った時の救済を入れるか。
→ リスク中。

## 第5部: やらないほうがいいこと

- **白基調の明るいマットにする** … 社長の「物理的にTCGしてる感じ・布の卓」と衝突する。
  ポケポケの白は「全年代に分かりやすく、モダン」を狙ったもので、うちの狙いとは違う。
  **やるならマットの色ではなく、カードの縁と影を強くしてカードを浮かせる方向**
- **カードデザインを寄せる** … 144枚の作り直しになる。割に合わない
- **3Dの傾きをやめる** … ポケポケも奥行きは付けている。今の傾きは強み
- **カードの視差シェーダを真似る** … 一度WebGLは「安っぽい」と判断して撤去済み。同じ轍を踏まない

## 第6部: 進め方の提案

1. **1-A ＋ 1-B**（ゾーン列を端へ／HPを大きく）… ここで見た目の印象が一番変わる
2. **3-A**（勝利までの距離を可視化）… 実装が軽いわりに体験が変わる
3. **2-A**（1タップ使用）… 手数が半分になる。誤タップ対策とセット
4. **1-C・1-D・2-C** … 余力で
5. **3-B**（山札切れ）… 社長判断。まず案2（警告表示）だけでも

1と3-A は既存の演出（踏み込み・被弾・VFX・カットイン）に触らないので壊れるリスクが低い。
各段階で13サイズの自動検査（2026-07-26 整備）を回して崩れを確認できる。
